# 技术长文 HTML

产出一个单文件 HTML 技术长文。版式是固定的，由 `scripts/build_article.py` 生成，你只负责**写正文 HTML 片段**：

- 全宽页面，中性灰白底，唯一强调色是蓝色；正文用系统无衬线字体，代码用等宽字体；自带深色模式。
- 页头：栏目小字、大标题（可含 `<code>`）、一句摘要、若干信息标签；阅读时长和章节数自动生成。
- 左侧是常驻的侧栏目录，直接列出每个 `<h2>` / `<h3>` 的编号和标题（`<h3>` 缩进），当前章节高亮并自动滚到可见处；左上角按钮可收起 / 展开，宽屏下记住选择，窄于 1100px 时默认收起、展开后浮在正文上方，点链接或按 Esc 关闭。顶部有阅读进度线。
- 每个 `<h2>` 是一节，节标题上方自动编号（01、02…）。节内按“行”排版：**说明文字在左，它解释的代码 / Prompt / 图在右**；文字较长时右栏吸附跟随。窄于 1320px（右栏放不下 600px 宽的图）时上下排列。
- 源码放深色面板（文件路径栏 + 复制按钮，自动语法高亮）；Prompt、Markdown、注入给模型的消息放浅色纸面面板（自动换行）；长内容默认折叠、可展开；图可点击放大。

## 用 Markdown 当源文件

正文可以不写 HTML 片段，改写一个 Markdown 源文件，由脚本生成同样的页面（页头字段也在这个文件里，不再走命令行参数）：

```bash
node <skill-dir>/scripts/md_to_article.mjs article.md            # 生成 article.html
node <skill-dir>/scripts/md_to_article.mjs article.md out.html --plan
node <skill-dir>/scripts/html_to_md.mjs 旧文章.html [article.md]  # 把 build_article.py 生成的旧页面反向转成 MD 源
```

- 两个转换器是 Node 脚本（标准库即可运行）；页头字段经临时 JSON 文件（`--fm-json`）传给 `build_article.py`，文章文本不出现在任何子进程的命令行里。

- front matter（`---` 包住）提供页头字段：`title`（反引号会变成 `<h1>` 里的 `<code>`）/ `kicker` / `deck` / `meta`（`- ` 列表）/ `footer` / `index`（返回目录页的相对链接）/ `updated`（固定 article-meta 的更新日期，缺省用当天） / `created`（创建时间，`2026-11-19` 或 `2026-11-19 14:30`；目录页默认按它倒序排列，缺省时按 `updated`。新文章写上创建时的日期和时间）。这些字段和正文一样按 Markdown 行内语法写（`` `code` ``、`**粗体**`、`[链接](url)`），`<`、`&` 直接写，脚本负责转义。
- 正文子集：段落（一段一行，不折行）、`-` 列表、`1.` 有序列表、`>` 引用、`##` / `###` 标题、GFM 管道表格（单元格里的 `|` 写成 `\|`，行内代码里也一样）；代码 / Prompt 面板和图都写围栏代码块，语言后跟 `title="…"`（文件路径或出处），可加 `wide` / `full` 标记：

  ````
  ```swift title="src/retry.ts"
  …代码…          ← swift / ts / py / bash 等走深色代码面板
  ```

  ```prompt title="prompts/retry-policy.md"
  …Prompt 原文…    ← prompt / md / text 走浅色纸面面板
  ```

  ```svg title="图 N：…" tone="light"
  <svg …>…</svg>   ← 图；深色图配 tone="dark"，超宽图加 wide
  ```
  ````
- 第一个 `##` 之前的列表会成为开头的要点卡（`data-points`）。
- 几个转写约定：围栏 `title` 保持页面里的 HTML 转义形式（标题含 `"` 时写 `&quot;`）；要把非 prose 语言（如 rust）放进浅色纸面面板，加 `kind="prompt"`；单元格 / 段落里需要换行直接写 `<br>`；内容本身含反引号的行内代码用 `` `` … `` `` 双反引号、前后各留一个空格。
- 左右配对规则与 HTML 片段完全一致：先写说明，再放它解释的面板；面板之后的列表 / 引用留在同一行左栏。`--plan` 的行划分和 WARN / ERROR 检查照常生效。
- 两个脚本互为逆运算：`html_to_md.mjs` 转出的 MD 再用 `md_to_article.mjs` 生成，应得到**字节相同**的页面；迁移旧稿后先 `cmp` 验证再覆盖原文件（旧模板生成的页面只有模板里的 CSS / JS 不同，正文与页头应仍逐字节一致）。
- 限制：手工着色源码（代码块内带 `<span>`）在 MD 里用 `raw` 围栏逐字节搬运——内容是已转义的 HTML，手改这类围栏要按 body 片段的转义规则写；`html_to_md.mjs` 会自动打上 `raw` 标记。

## 设计取向（用户明确要求过，不要改）

- 不用楷体、手写体等装饰字体；不加彩色手写批注（荧光笔、圈注、带箭头的标签、花括号、页边旁注、彩色便签）。强调靠 `<strong>`、行内 `<code>` 和左右对照本身。
- 不要在正文里写 `<style>`、`<script>`、行内 `style` 或自定义 class 来改样式；版式由脚本统一控制。
- 内容是主角：结论先行、短句、小标题用观点句（例如「哨兵展开机制：如何避免每轮重发长 Prompt？」，而不是「实现细节」）。
- 排版质感靠这几条，改模板时保持：正文段落最宽 720px（约 42 个汉字，左右栏上下堆叠时也一样）；只有代码 / Prompt 面板是带边框和阴影的卡片，图不加外框、最多按原始尺寸（至少 760px）显示，表格用三线表；表格和要点卡里的行内代码不加底色；节号显示为「01 / 09」。侧栏目录顶部显示文章标题，二级标题只在当前所读的节下展开。目录页是不带卡片的列表（左边是日期和栏目，右边是标题、摘要和一行信息），只能按栏目筛选。
- 可访问性已内置在模板里，改脚本时不要退回：页首“跳到正文”链接、标题锚点获得焦点时可见、面板标题自动换行不截断、放大图用原生 `<dialog>`、复制失败会如实提示、正文字号用 `rem`、次要文字（`--muted`）对各底色 ≥ 4.5:1、目录开关按钮带 `aria-expanded` / `aria-controls`，当前章节链接带 `aria-current`。

## 工作流程

### 1. 规划内容

- **标题**：讲什么 + 角度。**摘要**（`--deck`）：一句话说清全文结论或范围。
- **开头**（第一个 `<h2>` 之前）：1–2 段导语，可加一组要点卡 `<ul data-points>`（3–6 条）。
- **章节**：5–9 个 `<h2>`，需要时用 `<h3>` 细分。每节围绕“一段说明 ↔ 一块代码 / Prompt / 图”组织。
- 如果素材是现成文章或旧 HTML 报告：保留原有文字观点、源码、Prompt 原文和图，**一字不改地搬运代码与 SVG**，只重组结构。
- 素材里有**大段 Prompt**（超过约 20 行，或自带多个小节 / 列表）时，必须规划一节（或一组 `<h3>`）做逐段解读，不能只贴原文。要求见下文“大段 Prompt 的解读（必做）”。

### 2. 写正文片段

写一个只含正文的 HTML 文件（不需要 `<html>`、`<head>`、目录、页头）；也可以直接用 Markdown 写（见上文「用 Markdown 当源文件」），`md_to_article.mjs` 会把它转成同样的片段再走同一流程。用到的写法：

```html
<p>导语……</p>
<ul data-points>
  <li><code>getPromptForCommand()</code>：用户输入 /loop 的瞬间，Skill 如何展开</li>
  <li><code>ae.enqueue()</code>：每次触发如何把消息塞回上下文</li>
</ul>

<h2>观点式的节标题</h2>
<p>先说这段代码要看什么。</p>
<p>再点出关键行：第 6 行的 <code>base * 2 ** attempt</code>……</p>
<pre data-lang="ts" data-title="src/net/retry.ts"><code>export async function retry&lt;T&gt;(…) { … }</code></pre>
<blockquote><p>紧跟在面板后的引用块，会留在同一行的左栏，作为对这块代码的补充提醒。</p></blockquote>

<h3>小节标题会开启新的一行</h3>
<p>这段 Prompt 规定了……</p>
<pre data-lang="prompt" data-title="prompts/retry-policy.md"><code># Retry policy …</code></pre>

<figure data-diagram data-title="图 1：……" data-tone="light"><svg viewBox="0 0 640 180">…</svg></figure>

<table>…</table>   <!-- 表格独占整行 -->
```

- **代码 / Prompt 面板**：`<pre data-lang="…" data-title="文件路径或出处">`。`data-lang` 为 `prompt`、`md`、`text`（注入消息）时用浅色纸面面板，其余（`ts`、`rust`、`go`、`py`、`toml`……）用深色代码面板并自动高亮。`data-title` 必填，写文件路径（可带行号）或 Prompt 的出处。
- **代码必须转义**：`<` → `&lt;`、`>` → `&gt;`、`&` → `&amp;`，否则脚本报错。
- **已手工着色的源码**（改写旧报告时常见）：保留其中的 `<span class="kw|fn|str|cm|cmt|num|ty|typ">`，以及 `<span class="hl-line">`（蓝色重点行）、`<span class="hl-amber">`（橙色重点行）、Prompt 里的 `pr-h`（标题）/ `pr-b`（加粗）。含 `<span>` 的块不会再自动高亮。
- **图**：`<figure data-diagram data-title="图 N：……">` 里放 `<svg>` 或 `<img>`。图本身配色偏深（深底亮字）时加 `data-tone="dark"`；原始宽度超过 1000px 时加 `data-wide`（栏内横向滚动，点击可放大）。SVG 里的文字别依赖页面字体和字距，`font-family`、`font-size` 写在 SVG 上。
- **引用块** `<blockquote>`：注意事项、结论。不要用它包大段内容。
- **表格**：对比矩阵、属性表，独占整行。

**左右配对规则**（脚本自动执行，写的时候按这个顺序排）：

1. `<h3>` 开启新的一行。
2. 段落之后出现的面板，归入这些段落所在的行，显示在右栏。
3. 面板之后再出现**段落**，开启新的一行；面板之后紧跟的**列表或引用块**留在当前行左栏，当作对这块代码的说明。
4. 所以：**先写说明，再放它解释的面板**；一行的说明控制在 2–4 段（约 300–600 字）；一行最多放 2–3 个面板，多了用 `<h3>` 或新段落拆开。
5. 没有面板可对照的段落会按正常宽度（约 760px）排版，不会留出右侧空白。

### 大段 Prompt 的解读（必做）

Prompt 原文是这类文章最有价值的素材，但一整块 50 行的英文贴在右栏、左边只有一句“这是续跑提示词”，读者既不会读完，也看不出门道。所以只要 Prompt 超过约 20 行，或者自带多个小节 / 列表，就按下面的方式写：

1. **先给定位和结构**：这段 Prompt 什么时候注入、注入到哪里（新 turn、当前 turn、工具描述、错误返回……）、有哪些模板变量、负责什么不负责什么。再用一张表列出各段：段名、行号、这段让模型回答什么问题。
2. **按 Prompt 自己的小节切开，逐段成行**：每段原文单独一个面板，`data-title` 写成 `文件名:起-止行 · 段名`；左栏写这一段的解读。各段面板连起来要覆盖全文，不跳段、不改字（用脚本按行号抽取，不要手抄）。
3. **每段解读至少回答两点**：
   - 它针对模型的哪种失败模式或要解决什么问题（例如缩小目标、过早宣布完成、空转、为过测试走捷径、被注入的指令）；
   - 关键措辞为什么这样写：引用原文短语（英文原样放在 `“…”` 里），说明它堵住了什么漏洞，例如反转举证责任、同义词列表、给出反例、写明原因。
   有对应实现时，再说明它和代码如何配合：哪些规则代码也强制、哪些只能靠 Prompt。
4. **收尾**：一张“Prompt 规则 ↔ 代码约束”的分工表（有代码时），加上这段 Prompt 的弱点或局限（自我审计、长度、规则间的张力、与其他模板不一致处……）；同一主题有多份 Prompt（模板、工具描述、错误信息）时，每份都要解读，可以合成一节，最后给出可借鉴的写法。
5. 少于约 20 行的短 Prompt（单个工具描述、一句错误信息）不用切段，一行内“原文在右、解读在左”即可，但解读同样要讲清“为什么这样写”。

需要单独展示全文作对照时，给那个面板加 `data-full`，脚本就不会因为它过长而警告。

### 3. 生成并检查

```bash
python3 <skill-dir>/scripts/build_article.py body.html out.html \
  --title 'Claude Code <code>/loop</code> 真实源码拆解' \
  --kicker '源码拆解' \
  --deck '一句话摘要' \
  --meta 'Claude Code v2.1.325' --meta 'Prime Agent 源码对照' \
  --footer '源码出处：……' \
  --plan
```

- `--plan` 打印每节的行划分：`[split] 左栏文字摘要 → [右栏面板标题]`。逐行确认每块代码旁边是解释它的文字；配错了就调整正文顺序后重新生成。
- `ERROR` 必须修（未转义的代码、没有 `<h2>`、图里没有 SVG）；`WARN` 逐条判断（缺 `data-title`、一行面板过多、说明过长等）。
- 出现 `long prompt panel` 警告时，说明有一整块超过 30 行的 Prompt 没有切段，按“大段 Prompt 的解读（必做）”拆开；确实要展示全文对照时加 `data-full`。
- 有浏览器时截图核对：宽屏（≥1440px）、窄屏（≈900px）、手机（390px）、深色模式（`<html data-theme="dark">`）。

### 更新文章目录（index.html）

文章所在目录有 `index.html`（或用户要求一个目录页）时：

1. 生成文章时加 `--index index.html`，页头会出现“← 全部文章”的返回链接。
2. 每次新增、改名、删除文章后运行：

```bash
python3 <skill-dir>/scripts/build_index.py <文章目录> [--title '技术文章']
```

子文件夹里如果也有用它生成的 `index.html`（例如按主题建的 `deepseek/`），会在目录页顶部显示为“专题”入口；给子文件夹生成目录页时加 `--back ../index.html`，页头会出现“← 上级目录”。子文件夹里的文章 front matter 写 `index: index.html`，返回的是本文件夹的目录页。

它读取每篇文章里由 `build_article.py` 嵌入的元数据（标题、摘要、标签、章节、阅读时长、更新日期），生成可搜索、按标签筛选、可排序、能直接跳到各章节的目录页。不是用本 skill 生成的页面也能收录，只是信息少一些（用 `<title>`、description 和 `<h2>`）。目录页的配色、字体和文章一致，同样支持深色模式；按 `/` 键聚焦搜索框。

`assets/example-body.html` 是一份完整示例正文，`assets/example.html` 是它的生成结果，可以直接对照写法。

### 4. 交付

告诉用户文件路径、章节结构、每节左右分别放了什么；改写旧页面时说明哪些内容原样保留、哪些结构有变化。不要贴整段 HTML。

## 改写已有 HTML 报告

1. 先完整读一遍原文件，列出所有代码块、Prompt、SVG 图、表格和说明文字。
2. 用脚本按出现顺序把 `<pre>` 内容和 `<svg>…</svg>` **原样**抽出来，不要手抄，避免改坏字符。
3. 按上面的配对规则重新组织正文；原来的标签页、卡片网格、侧边导航等交互都改成线性的节和行。
4. 生成后用脚本比对：原文件里的每段代码和每个 SVG 都必须在新文件里原样出现。
5. 原文自相矛盾或明显有误的地方（数字、版本前后不一致）不要擅自改，交付时指出来让用户决定。
